# Tenmayurika — переносная память на M.2

## Личная библиотека

Файлы находятся в `data/library` на диске проекта. После установки зависимостей библиотека работает без интернета и подключения к облачному хранилищу. Максимальный размер загружаемого файла — 1 ГБ. При совпадении имени можно сохранить оба файла или подтвердить замену: перед заменой предыдущая версия копируется в `data/library-versions`, её можно скачать в разделе «Предыдущие версии».

«Хранитель» читает TXT, Markdown, CSV, JSON, DOCX, XLSX и PDF с текстовым слоем, показывает выдержки и ищет по содержимому. По запросу он распознаёт PNG, JPEG, WebP и сканированные PDF локально на русском и английском; результат можно сохранить рядом с оригиналом. OCR ограничен 16 МБ, 10 страницами PDF и 8 мегапикселями на страницу. Распознавание может ошибаться. Формулы Excel не пересчитываются; показываются сохранённые значения ячеек. В обзоре Excel показываются первые 20 строк каждого листа, до пяти книг одновременно.

Очередь фоном обрабатывает новые и изменённые документы, пока проект запущен. Извлечённый текст локального поискового индекса хранится в той же SQLite на SSD; фоновую обработку можно отключить. При изменении или удалении исходника устаревшие результаты пропускаются. Проверка изменения использует размер и время изменения, а не контрольную сумму. Поиск по смыслу здесь основан на совпадении слов, не на языковой модели; фрагменты ответа необходимо сверять с источником. Часть операций ограничена 200 файлами или 5000 записями — интерфейс предупреждает, если проверена только часть библиотеки.

Подборки и связи ссылаются на файлы, не копируя их. Порядок в папках, предложенные имена и факты применяются только после действий пользователя. Подтверждённые факты и личные заметки/дела библиотеки остаются локальными и отделены от общей памяти и планера, чтобы не передавать документ в облачную модель. Для личного дела можно указать дату и время: напоминание показывается, пока открыт проект; системные уведомления требуют разрешения браузера. Команды чата «найди в библиотеке ...», «спроси библиотеку ...» и «спроси файл папка/имя.pdf: вопрос» выполняются локально, а их результаты исключаются из контекста модели и истории браузера.

Автоматическая копия SQLite включает индекс, но не включает оригиналы файлов библиотеки и предыдущие версии. Для полной копии закройте приложение и выполните `node tools/backup-complete.js`: в неё войдут SQLite, `data/library`, версии, подборки, очередь и журнал. Храните дополнительную копию на другом устройстве. На диске без жёстких ссылок при переносе или переименовании исходный файл сохраняется, а в интерфейсе показывается предупреждение.

## Архитектура

- **SQLite** (`data/tenmayurika.sqlite`) — заметки, задачи и узлы/рёбра графа. Отдельный сервер не требуется.
- **LanceDB** (`data/vectors/`) — векторный индекс заметок, без сервера.
- **Node.js 24+** — локальный веб-сервер и встроенный модуль `node:sqlite`.

PostgreSQL, Qdrant и Neo4j больше не используются. Их прежние настройки удалены из `.env.example`, а драйверы — из `package.json`.

## Запуск с внешнего M.2 SSD (Windows x64)

1. Один раз загрузите **полный ZIP-дистрибутив Node.js 24+ для Windows** и распакуйте в `runtime/node/` на SSD (включая `npm.cmd`).
2. На компьютере с интернетом запустите `Tenmayurika.bat`: он установит npm-зависимости в `node_modules` на SSD. LanceDB использует нативные библиотеки, поэтому архитектура Windows и совместимость Node.js должны совпадать.
3. Для следующих запусков на совместимых Windows-компьютерах используйте тот же BAT. BAT проверяет LanceDB, PDF, OCR и языковые пакеты и при отсутствии компонентов восстанавливает зависимости. Офлайн-запуск возможен при заранее подготовленных совместимых зависимостях, но не гарантирован на любой версии Windows.
4. Адрес интерфейса: `http://127.0.0.1:5173`. Для остановки закройте процесс приложения перед извлечением SSD.

Папка `data/` не отправляется в GitHub. Не запускайте одну копию базы одновременно на разных компьютерах.

## Перенос данных

При первом запуске SQLite автоматически импортирует `data/workspace.json`, если он существует, и создаёт узлы графа для заметок. Исходный JSON не удаляется. **Если раньше использовался PostgreSQL, сначала экспортируйте данные из него в `data/workspace.json`**: прямого мигратора PostgreSQL пока нет.

## Семантический поиск

Выберите модель эмбеддингов в меню аватара → «Модель ИИ» → «Поиск по смыслу» (тот же адрес и ключ, что у модели) или скопируйте `.env.example` в `.env` и настройте OpenAI-совместимый embedding API. При добавлении заметки её вектор сохраняется в LanceDB. Поиск доступен по `GET /api/search?q=...`. Без embedding API заметки и задачи работают в SQLite, но векторная индексация отключена. Векторная индексация исторических заметок и автоматические повторные попытки ещё не реализованы.

## API и проверки

- `GET /api/health` — состояние сервера.
- `GET /api/services` — состояние SQLite, LanceDB и графа.
- `GET /api/graph` — узлы и связи графа.
- `GET /api/search?q=...` — семантический поиск.
- `npm test` — автоматические тесты.

**Ограничения:** нативные бинарные зависимости LanceDB могут потребовать совместимого Windows/CPU; режим полностью без предварительной загрузки компонентов пока не реализован. Перед извлечением SSD корректно завершайте приложение и делайте резервные копии SQLite и LanceDB.

## Резервные копии и синхронизация

`POST /api/backup` создаёт согласованную резервную копию SQLite в `backups/`. Векторный индекс LanceDB в неё не включён: для полного бэкапа отдельно копируйте `data/vectors` после остановки приложения. `POST /api/sync` запускает повторную индексацию ожидающих заметок. Фоновый обработчик повторяет попытки каждые 60 секунд при настроенном embedding API. Очередь сохраняется в SQLite. Без embedding API она остаётся ожидающей. Старые заметки, созданные до введения очереди, могут потребовать повторной индексации.

**Проверки:** реальный запуск BAT на Windows, тесты с Node.js 24 и восстановление полного комплекта SQLite + LanceDB ещё не подтверждены.

## Новый переносной запуск

`Tenmayurika.bat` запускает `tools/launcher.js` через Node.js 24+. Перед стартом проверяются доступность зависимостей, запись в папки, порт 5173 и `PRAGMA quick_check` SQLite. Браузер открывается только после ответа `/api/health`. Запуск второго экземпляра при занятом порте блокируется без завершения чужого процесса.

Команды из CMD в корне проекта:

- `Tenmayurika.bat` — обычный запуск;
- `Tenmayurika.bat doctor` — диагностика окружения и SQLite;
- `Tenmayurika.bat backup` — резервная копия SQLite в `backups/`.

Первый запуск требует интернет для `npm install`, если зависимости ещё не подготовлены на SSD. Для `doctor` и `backup` зависимости должны быть подготовлены заранее. Копия SQLite не содержит `data/vectors`; перед переносом или полным бэкапом остановите приложение и скопируйте обе папки. Автоматическое восстановление, контроль свободного места, автоматические обновления и тестирование на реальной Windows пока не реализованы.

## Один BAT — автоматическая подготовка

Запускайте только `Tenmayurika.bat`. Если Node.js 24+ не найден, BAT вызывает `tools/bootstrap-node.ps1`: загружает официальный ZIP Node.js 24 x64 с nodejs.org, сверяет SHA-256 по официальному SHASUMS256.txt и распаковывает в `runtime/node`. Затем при отсутствии LanceDB автоматически запускает `npm install`. Повторный запуск использует подготовленные файлы с SSD без загрузки. Для первоначальной подготовки нужен интернет и доступ к nodejs.org и npm registry. PowerShell вызывается без изменения системной политики выполнения; глобальная установка Node.js и Docker не требуются. Для диагностики и бэкапа используются команды `Tenmayurika.bat doctor` и `Tenmayurika.bat backup`. Не отключайте SSD во время работы.

Это автоматизация подготовки, а не гарантия совместимости с любой Windows: требуются Windows x64, доступный PowerShell и совместимые нативные модули LanceDB. Проверка реального запуска на Windows остаётся обязательной.

## Автоматический Python и свободные порты

Единственная точка входа — `Tenmayurika.bat`. При отсутствии `runtime/python/python.exe` вызывается `tools/bootstrap-python.ps1`: сначала проверяется системный Python 3.10+, затем при необходимости загружается официальный встраиваемый Python 3.13.9 x64 в `runtime/python`. Этот вариант Python не содержит pip и не заменяет полноценную среду разработки. Если подготовка Python не удалась, основной Node.js-сервер всё равно может запускаться; ошибка отображается в консоли. Загрузка Python осуществляется по HTTPS, но независимая проверка SHA-256 пока не реализована.

Запускатель проверяет доступность TCP-порта на `127.0.0.1`, начиная с `PORT` (по умолчанию 5173), и перебирает до 30 следующих портов. Выбранный порт передаётся серверу и используется для ожидания `/api/health` и открытия браузера. Проверка порта не гарантирует отсутствие гонки между проверкой и фактическим запуском; при конфликте сервер завершится с ошибкой, не затрагивая чужие процессы. `Tenmayurika.bat doctor` показывает найденный свободный порт.

## Проверка Windows-путей и русификации

Основной `Tenmayurika.bat` выводит русские сообщения в UTF-8 (кодовая страница 65001), использует пути относительно `%~dp0`, заключает пути в кавычки и отключает delayed expansion. Запуск через `pushd` поддерживает смену диска. В GitHub Actions добавлена проверка на Windows в каталоге с кириллицей, пробелами, скобками и символом `&`. Результат CI следует проверить в разделе Actions: создание workflow само по себе не подтверждает успешного выполнения. Запуск в каталогах с `%` и `!` требует отдельной проверки, особенно если путь передаётся через CMD.

## Защита запуска и диагностика (текущий этап)

Запускатель теперь проверяет свободное место (минимум 512 МиБ), предупреждает о длинных путях и малом объёме доступной RAM, выбирает свободный loopback-порт, проверяет целостность SQLite и пробует загрузить нативный модуль LanceDB в режиме `doctor`. Во время работы создаётся `data/launcher.lock` с PID, предотвращающий обычный повторный запуск. После штатного завершения блокировка удаляется; после аварии устаревшая блокировка может быть снята после проверки PID. Перед извлечением SSD приложение нужно остановить.

Резервная копия SQLite проверяется командой `PRAGMA quick_check`, а рядом записывается `.sha256` с контрольной суммой. Это не полноценный архив всех данных: векторы LanceDB в копию не входят. Нельзя считать восстановление из бэкапа проверенным без отдельного теста восстановления.

Обработчик сервера проверяет точный Host и Origin на локальном порту и не записывает в журнал содержимое исключений HTTP-запросов. Фоновая индексация также не записывает полный текст ошибок провайдера. GitHub Actions содержит проверки синтаксиса и запуск BAT в каталоге с кириллицей, пробелами, скобками и `&`; успешность CI следует проверять отдельно.

**Ещё не реализовано полностью:** транзакционная установка npm с откатом, автоматический откат обновлений, согласованный полный бэкап SQLite + LanceDB, защита от физического отключения SSD, ротация журналов, проверка всех специальных символов Windows, гарантия корректного завершения дочернего процесса при принудительном закрытии окна. Запуск не должен удалять повреждённые данные автоматически.

## Автоматические резервные копии

Пока сервер работает, каждые **5 часов** выполняется резервное копирование SQLite в `backups/automatic/`. После успешного создания новой копии, проверки `PRAGMA quick_check` и записи файла `.sha256` предыдущие автоматические копии SQLite удаляются. Если создание новой копии завершилось ошибкой, прежняя копия сохраняется. Одновременные запросы используют одну операцию копирования. Предыдущие ручные копии в `backups/` не затрагиваются. Копирование не запускается, когда программа выключена, и отсчёт начинается при каждом запуске сервера. **Важно:** векторная база LanceDB и другие файлы проекта не входят в эту копию; хранение только одной копии не защищает от незаметной порчи данных, обнаруженной позже. Для долговременной защиты нужен отдельный архив на другом носителе.

### Проверка созданной резервной копии

Для отдельной проверки контрольной суммы и полной целостности SQLite используйте `node tools/verify-backup.js backups/automatic/ИМЯ_ФАЙЛА.sqlite`. Команда не меняет базу и завершается с кодом 1 при повреждении файла или контрольной суммы. Тест `tests/backup-integrity.test.js` создаёт временную SQLite, проверяет корректную копию и намеренно повреждённый файл. Проверка и хеширование выполняются блоками по 1 МиБ без загрузки всей копии в оперативную память. Это **проверка архива, а не автоматическое восстановление**.

## Полное офлайн-резервирование

Закройте приложение, затем выполните `node tools/backup-complete.js`. Создаётся отдельная папка в `backups/complete/` с SQLite, копией `data/vectors` и `manifest.json` (SHA-256). Полные копии автоматически не удаляются. Эта команда не заменяет пятичасовой бэкап SQLite. Полное резервирование требует отсутствия других процессов, записывающих данные; автоматическое восстановление пока не реализовано.

Полная офлайн-копия теперь автоматически проверяется после создания. Для повторной проверки используйте `node tools/verify-complete.js backups/complete/ИМЯ_СНИМКА`. Проверяются контрольные суммы всех зарегистрированных файлов и целостность SQLite. Проверка не является восстановлением; копирование по-прежнему требует остановки всех процессов записи.

## Автоматическое обслуживание

При запуске BAT проверяется загрузка dotenv и нативного LanceDB; при ошибке выполняется `npm install` и повторная проверка. `doctor` дополнительно сообщает версии npm и переносного Python (Python необязателен). Сервер проверяет возможность чтения/записи и не менее 512 МиБ свободного места перед запросами на изменение данных; при сбое отвечает ошибкой. Раз в час проверяется диск и удаляются только устаревшие временные пробы и большие журналы старше 7 суток. SQLite, LanceDB и резервные копии очистка не трогает. Фоновые векторные задания имеют предел 5 неудачных попыток; если таблица LanceDB `notes` отсутствует, заметки SQLite ставятся в очередь переиндексации. Проверка отсутствующих отдельных векторов и таймаут зависшего нативного вызова пока не реализованы. Запуск тестов: `npm.cmd test`.

## Дополнительная автоматизация памяти и очереди

Каждый час при настроенном EMBEDDING_URL фоновый процесс сравнивает ID заметок SQLite с ID в таблице LanceDB `notes` и ставит отсутствующие записи на повторную индексацию. Повторы ограничены пятью попытками с задержкой от 30 секунд до часа; существующая таблица очереди автоматически расширяется колонкой `next_retry_at`. Периодические проверки диска выполняются каждый час, при запуске и при запросе `/api/health`; запись блокируется, если контроль диска не пройден. Ограничение: сверяются ID, а не хеш содержимого; зависшие вызовы нативной LanceDB пока нельзя безопасно прерывать в том же процессе.

## Факты памяти в интерфейсе

Раздел «Факты» в боковом меню работает с `memory-core.js`: можно добавить факт «субъект — связь — объект», искать по фактам (без учёта регистра, в том числе для кириллицы), открыть все связи субъекта щелчком по нему и посмотреть противоречия, то есть разные объекты у одной пары субъект–связь. Строки вида `FACT: Анна | живёт в | Казань` в тексте новой заметки автоматически сохраняются как факты с источником `note:<id>`.

API:

- `GET /api/facts?q=...` — поиск, `GET /api/facts?subject=...` — факты субъекта, без параметров — последние факты;
- `POST /api/facts` с JSON `{subject, predicate, object, confidence?, sourceId?}` — добавить факт (201 — новый, 200 — дубликат);
- `GET /api/facts/relations?subject=...` — связи, где субъект стоит с любой стороны;
- `GET /api/facts/conflicts` — противоречия;
- `GET /api/facts/diagnostics` — целостность и счётчики.

## Слои памяти «Мозга» (идеи MemOS)

Идеи взяты из [MemTensor/MemOS](https://github.com/MemTensor/MemOS) (Apache-2.0), код не копировался.

- **Польза записей** (`usefulness.js`): 👍/👎, «верно» или поправка переходят на вспомненные факты и заметки; поиск ставит выше то, что помогало. Сила памяти считается и на сервере (`GET /api/brain/strength`).
- **Поправка словами меняет факты** (`correct.js`): «нет, Анна живёт в Перми» запоминает новый факт, а спорящий старый уходит в историю.
- **Предпочтения** (`preferences.js`): «отвечай короче», «без смайликов», «называй меня Аня» хранятся отдельно и всегда идут модели.
- **Рабочая память темы** (`working.js`): записи из последних сообщений подаются без нового поиска; новый чат начинается с нуля.
- **Безопасная подача памяти**: вспомненное идёт модели в блоке `<память>` как данные, строки, похожие на команды, помечаются; слабые находки отсекаются, похожие прореживаются (MMR).
- **Навыки из опыта** (`skills.js`): несколько подтверждённых похожих ответов дают правило «на такой вопрос делай так».
- **Размышления в простое** (`reflect.js`): после 10 минут тишины (`TENMAYURIKA_IDLE_MS`), не чаще раза в час и только если есть новое, мозг обновляет сводки тем, ищет причинные связи (`links.js`), выводит навыки и выводы и пишет дневник. Всё это видно в «Мозге» → «✦ Дневник» (`GET /api/brain/mind`, `POST /api/brain/reflect`), а в чате по команде «дневник».

## Навыки запоминания и самоучёба (идеи MemSkill)

Идеи взяты из [ViktorAxelsen/MemSkill](https://github.com/ViktorAxelsen/MemSkill) (Apache-2.0), код не копировался. Навык запоминания — не факт и не опыт, а способ запоминать: что вытаскивать из текста и что обновлять или отставлять.

- **Банк навыков** (`memskills.js`): люди и отношения, время и даты, занятия, где лежат вещи, ограничения, работа и места, сроки дел, «обновить известное», «отставить устаревшее». Под каждый текст подбираются 2–3 навыка по словам-подсказкам, отдельно для чата, заметок и дел; разбор моделью идёт одним вызовом.
- **Операции записи** (`learn.js`): модель видит похожие известные факты и отвечает `FACT` (новое), `UPDATE` (новая версия, старая уходит в историю) или `RETIRE` (явно отменено). Без модели работают прежние правила.
- **Статистика**: сколько раз навык выбирали, польза записанных им фактов (👍/👎), бонус на пробу новым, бесполезные уходят на покой.
- **Журнал промахов**: самоэкзамен и поправки дают промахи с причиной (не записано, не нашлось, размыто); очередь «о чём подумать» = тяжесть × повторы, старше 30 дней выпадают.
- **Самоучёба в простое** (`selfstudy.js`, из `reflect.js`): экзамен по недавней переписке; разбор промахов кругами (разбор → самокритика → предложение, не больше двух изменений); проба на текстах промахов — изменение остаётся, только если стало лучше; затем старые сообщения перечитываются заново. Если с новым банком экзамен хуже лучшей прошлой версии на 15 пунктов, банк откатывается. После трёх неудач подряд она просит подсказку, и подсказка становится навыком. Выводы в простое тоже проходят самопроверку.
- **В «Мозге»**: навыки — органы на орбите ядра (размер = применения, мерцание = проба), а в «✦ Дневнике» раздел «чему я научилась запоминать» (`GET /api/brain/memskills`, `POST /api/brain/memskills/hint`).

## Сердцевина и разговор (идеи letta-code)

Идеи взяты из [letta-ai/letta-code](https://github.com/letta-ai/letta-code) (Apache-2.0), код не копировался.

- **Сердцевина** (`core.js`): три блока, которые всегда в подсказке модели: «Кто я», «Кто ты», «Как мы общаемся». Предел 1500 символов на блок (`TENMAYURIKA_CORE_LIMIT`). Юрика правит их сама, а в простое пересматривает по свидетельствам (факты о «Я», просьбы, поправки, дневник). Блок правится как текст, а не журнал: похожее сводится в принципы, устаревшее уходит. Каждая правка — версия, любую можно вернуть. Без модели «Кто ты» собирается из фактов о «Я».
- **Самоправка в чате**: инструменты `correct_fact`, `forget_fact`, `core_memory_append`, `core_memory_replace`, `core_memory_rewrite` (переключатель «Запоминать факты»). Команда «сердцевина» показывает блоки.
- **Сжатие разговора** (`convo.js`): браузер шлёт до 40 сообщений и номер разговора. Последние 12 модель видит дословно, а более ранние сворачиваются в сводку «Раньше в этом разговоре». Сводка копится фоном: с моделью это пересказ, без неё выдержки.
- **Разбор на ходу** (`review.js`): каждые 20 сообщений (`TENMAYURIKA_REVIEW_EVERY`) и при первом сжатии разговора. Порядок такой: ошибки → предпочтения → факты → противоречия → понимание человека. Если ничего не нашлось, ничего не меняется.
- **Вспоминание по датам** (`dates.js`, `chatlog.between`): «о чём мы говорили вчера», «что я рассказывал в понедельник про Анну»; сюда же инструмент `recall_conversation`.
- **Оглавление памяти** (`atlas.js`): в подсказке всегда лежат зоны с размером и сводкой. Зону целиком открывает `open_zone` или команда «покажи зону Анна».
- **Знакомство** (`onboarding.js`): Юрика хочет узнать 7 вещей о человеке: имя, работа, где живёт, близкие, увлечения, что главное сейчас, как отвечать. Пункт закрывается сам, когда в памяти появляется факт. Вопрос задаётся не чаще раза в 3 сообщения (`TENMAYURIKA_ONBOARD_EVERY`).
- **В «Мозге»** в «✦ Дневнике» есть разделы «сердцевина» (правка и возврат версий), «знакомство» и строка разбора разговора. API: `GET/POST /api/brain/core`, `POST /api/brain/core/restore`, `POST /api/brain/onboarding`, `POST /api/brain/review`, `GET /api/brain/atlas`.

## Логика и рост «Мозга»

- **Вопрос в контексте разговора** (`context.js`): «а она где работает?» ищется вместе с тем, о ком шла речь; «а Оля?» берёт суть прошлого вопроса.
- **Учёба с контекстом** (`chatlog.js`, `learn.js`): сообщение разбирается вместе с прошлым вопросом Юрики и соседними репликами; короткий ответ («Маша» на «как зовут сестру?») тоже запоминается.
- **Честное «не знаю»** (`inner.personal`): если о личном ничего не нашлось, модель не выдумывает, а черновик сверяется с пустой памятью.
- **Логические выводы** (`infer.js`): взаимные связи, родство через шаг (бабушка, дядя, брат или сестра), возраст из дня рождения, место через место. Выводы не пишутся в память, а считаются заново и идут в подсказку с цепочкой «потому что».
- **Противоречия и планы в разговоре** (`curiosity.js`, `plans.js`): Юрика сама спрашивает, какая версия верна, а срок из «в следующем месяце переезжаю» привязывается к дате; когда он прошёл — спрашивает, сбылось ли.
- **Подтверждение повтором** (`evidence.js`): то же самое из другого источника повышает уверенность (один раз на источник).
- **Поиск фактов по смыслу** (`factvec.js`): модель эмбеддингов выбирается в «Модель ИИ» → «Поиск по смыслу» (на Cloud.ru, например, `BAAI/bge-m3`); векторы фактов хранятся в SQLite.
- **Самонастройка поиска** (`tune.js`): веса способов вспоминать подстраиваются по 👍/👎 и пробе на вопросах самоэкзамена; изменения видны в мыслях и дневнике.

Всё выключается в настройках мышления «Мозга».

## Зафиксированные версии зависимостей

`package-lock.json` хранится в репозитории. Когда BAT восстанавливает зависимости, при наличии lock-файла он вызывает `npm ci`, поэтому на любом компьютере ставятся одни и те же версии LanceDB и dotenv. В CI тоже используется `npm ci`.

## Интерфейс и аватар

Интерфейс — чёрно-золотая тема с жидкой вёрсткой (`clamp()`, автоматический масштаб шрифта и отступов) от телефона до ультрашироких и 4K-мониторов. Слева — вертикальное меню из значков (SVG), внизу — значок аватара и «Настройки проекта».

Аватар-кицунэ (`avatar.js`, изображения в `assets/avatars/`: полное разрешение ~1240 px плюс 768 px и миниатюры, браузер выбирает размер через `srcset`) находится поверх всего интерфейса:

- **перетаскивание** мышью или пальцем (или стрелками с клавиатуры), позиция запоминается;
- **левый клик** или **Alt+Y** — чат, привязанный к аватару (окно следует за ним, на телефоне — нижняя шторка); история хранится в браузере, есть кнопки быстрых действий;
- **правый клик** (долгое нажатие, Shift+F10) — большое меню с разделами:
  - *Образ*: 5 поз, имя, размер 80–720 px, непрозрачность, наклон, отражение, яркость, насыщенность, оттенок;
  - *Свечение и магия*: 7 цветов + свой, сила и пульсация, магический круг, блик света, золотой контур, тень;
  - *Частицы*: искры, сакура, кицунэ-би, светлячки, звёзды, снег, бабочки, руны; количество, скорость, размер, искры при клике, след при движении;
  - *Движение и характер*: парение, дыхание, реакция на наведение, живые позы, смена поз, прогулки, взгляд на курсор, реплики;
  - *Инструменты*: карточки с переключателем для каждого инструмента;
  - *Модель ИИ*: Cloud.ru Foundation Models или любой OpenAI-совместимый сервис;
  - *Чат и уведомления*: размер окна и текста, Alt+Y, звук и системные уведомления, список напоминаний, экспорт/импорт.

Настройки сохраняются в `localStorage` между запусками.

### Инструменты аватара

Чат работает через `POST /api/chat`. Явные команды выполняются сразу, даже без языковой модели:

| Команда | Действие |
| --- | --- |
| `заметка: Заголовок — текст` | создать заметку |

| `напомни через 10 минут позвонить`, `таймер 30 с`, `помодоро` | напоминания (звук и уведомление) |

### Дела, заметки и календарь

**Планер** (значок календаря в левом меню) объединяет дела, календарь и заметки на одном экране:

- **Сверху** строка быстрого ввода. Можно писать «созвон завтра в 10 #работа !» или «заметка: Идея — текст», и дата, время, категория и важность разберутся сами. Там же прогресс дня и переключатель видов: Список, День, Неделя, Месяц, Заметки.
- **Слева** мини-календарь, фильтр «Все / Личные / Работа» и умные списки: Сегодня, Ближайшие 7 дней, Просрочено, Без срока, Все дела, Выполнено, Заметки.
- **В центре** выбранный вид. Дела можно перетаскивать на день (месяц, неделя, мини-календарь) или на час (вид «День»).
- **Справа** карточка выбранного дела или заметки. Если ничего не выбрано, там дела выбранного дня и «Заметка дня», которая сохраняется сама.
- Удаление можно отменить кнопкой «Вернуть».
- Клавиши: N — новое, 1–5 — вид, T — сегодня, ← → — листать, / — поиск, Esc — снять выбор.

- **Дела**: личные 🏠 и рабочие 💼, срок (дата и время), важность. Есть фильтр по категории и поиск. Дела разбиты на группы: просрочено, сегодня, ближайшие 7 дней, позже, без срока и выполнено. Каждое дело можно редактировать и удалять.
- **Заметки**: карточки с категорией, поиском и закреплением 📌.
- **Календарь** (значок в левом меню): сетка месяца с делами по дням. Нажмите на день, чтобы увидеть его дела и быстро добавить новое.
- Значок на «Делах» показывает, сколько дел на сегодня и просрочено. Аватар напоминает о делах со временем и раз в день даёт утреннюю сводку. Это настраивается в её меню → «Чат и уведомления».
- API: `POST/PATCH/DELETE /api/items`, поля `category` (personal|work), `due` (ГГГГ-ММ-ДД), `time` (ЧЧ:ММ), `priority` (low|normal|high), а для заметок `pinned`. Удалять записи может только пользователь в интерфейсе, у аватара такого инструмента нет.

| Команда в чате | Что делает |
|---|---|
| `дело: купить чай завтра в 18:00` | дело с датой и временем |
| `рабочее важное дело: отчёт в пятницу` / `работа: созвон в 10:00` | рабочее дело |
| `рабочие дела`, `личные дела на завтра`, `дела на неделю`, `просроченные` | списки дел |
| `что на сегодня`, `что на неделе`, `повестка` | план с просроченными делами |
| `перенеси отчёт на понедельник в 11:00` | перенос дела |
| `сколько дней до 31.12` / `до нового года` | счёт дней |
| `рабочая заметка: План — пункты` | рабочая заметка |
| `переведи 5 км в мили`, `сколько 100 f в c` | конвертер единиц |
| `придумай пароль на 20` | пароль создаётся на этом компьютере |
| `выбери чай, кофе или какао` | случайный выбор |

### Модель ИИ (Cloud.ru)

Меню аватара → «Модель ИИ»: выберите «Cloud.ru Foundation Models» (адрес `https://foundation-models.api.cloud.ru/v1` подставляется сам), вставьте ключ API, нажмите «Загрузить список моделей», выберите модель и «Сохранить». Кнопка «Проверить связь» отправляет короткий тестовый запрос. Там же настраиваются креативность, длина ответа, характер (системная подсказка) и разрешение на инструменты.

Настройки и ключ хранятся локально в `data/llm-settings.json` (права 0600, папка `data/` не попадает в git); ключ никогда не возвращается в браузер — интерфейс видит только последние 4 символа. Можно указать любой OpenAI-совместимый сервис по `https://` или локальную модель по `http://127.0.0.1`. Если модель не поддерживает инструменты, запрос автоматически повторяется без них. Без сохранённых настроек используются переменные `.env` (`CHAT_URL`, `CHAT_API_KEY`, `CHAT_MODEL`), а без них аватар отвечает локально по фактам и заметкам. Выключенные инструменты сервер не выполнит ни по команде, ни по просьбе модели. Удаляющих инструментов нет.

API: `GET /api/llm` (настройки без ключа), `POST /api/llm` (сохранить), `POST /api/llm/models` (список моделей), `POST /api/llm/test` (проверка связи).

Строки фактов в заметках принимаются в двух форматах: `FACT: субъект | связь | объект` и `FACT: | субъект | связь | объект`.

Для тестов путь к базе можно изолировать переменными `TENMAYURIKA_DATA_DIR` (SQLite заметок и дел) и `TENMAYURIKA_MEMORY_DB` (факты).
